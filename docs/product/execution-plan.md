# 功能依赖顺序

本文说明功能之间的先后依赖，便于参与者选择可独立推进的功能点；不包含人员分配、迭代周期或工作量估算。详细边界与验收条件见 [功能任务卡](feature-backlog.md)，产品规则见 [生产平台功能规格](production-platform-spec.md)。

## 主依赖链

```text
D-01a 来源/叙事/视频路径模型
  ├── D-01b 旧项目兼容
  ├── D-02a 数据迁移基线
  └── D-03a 来源发布版本 → D-03b 阶段产物与门禁 → D-03c stale 传播

D-03b → J-01 持久任务合同 → J-02 派发/Worker/恢复
                  └── P-01 Provider 能力/校验/成本 → P-02 配置

D-03a → SRC 输入与来源证据 ─┐
D-03a → AS 资产身份/版本/引用 ├→ STORY 内容规划与剧本 → SHOT 分镜
J-02 + P-01 ────────────────┘                         ├→ IMG 关键帧
                                                       ├→ VID 视频
                                                       └→ VOICE 配音

持久任务 + Agent 计划/节点合同 → AGENT 运行图/审核 → Agent 控制台
IMG + VID + VOICE → TL 时间线 → 合成/质量检查 → 工程导出
商品事实与证据 → 广告脚本 → 共享资产/媒体/时间线交付
三种入口闭环 → QA 场景验收 → OPS 部署/恢复/运维
```

## 依赖说明

- **领域基础优先**：D-01a、D-03a/b 定义统一入口、来源版本和阶段门禁。后续内容及媒体阶段都引用这些合同，避免按入口类型硬编码生成能力。
- **任务与 Provider 并行**：J-01/J-02 提供可恢复执行；P-01/P-02 负责能力发现、参数校验和用量。Worker 接入具体 Provider 前需要两边合同明确。
- **内容与资产协作**：SRC、AS 可在来源合同稳定后分别建设；STORY 需要来源证据和资产引用能力，之后进入分镜与媒体生成。
- **媒体之后再编辑**：关键帧、视频和配音必须形成可审核且版本化的候选，时间线只能引用已接受的媒体版本。
- **Agent 是编排层**：运行图基于既有阶段、任务、产物和门禁；不能代替业务服务或绕过人工审核。画布只展示服务端真实执行状态并调用允许的控制操作。
- **广告复用底座、保持独立规则**：商品事实与证据账本先建立，广告脚本通过共享资产、Provider、媒体和时间线能力完成交付。
- **端到端验收最后收口**：小说导入、AI 原创和商品广告分别覆盖失败恢复、人工审核、版本过期、合成及工程导出。

## 可并行功能边界

- Provider 能力目录与资产身份/版本可在共享来源和产物合同冻结后分别实现。
- 各工作台 UI 可在各自 API/schema 冻结后并行开发，不自行模拟后端任务或候选状态。
- Agent 运行图和时间线编辑可分别在任务/产物合同基础上推进；二者通过已接受的媒体版本衔接。
- 共享 ORM、迁移和核心 API schema 应按依赖顺序变更；并行分支先明确文件与实体边界，减少集成冲突。

## 当前状态

本文列出的功能均属于待实现/待验收范围。建议从 **D-01a** 起步，完成后按任务卡前置条件领取后继功能；只有验收证据完整的功能点才能标记完成。
