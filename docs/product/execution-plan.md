# 叙帧执行计划

本计划是 [开发路线图](development-roadmap.md) 的迭代排程视图。具体可领取功能点见 [功能任务卡](feature-backlog.md)。本计划把依赖顺序、建议负责人角色、粗略工作量和完成出口放到一起，供后续分配给内部或外部开发者。

## 排程假设

- 以 **2 周一个迭代** 做初始排程；按相对迭代编号执行，不填虚假的日历日期。
- 容量假设为 2 名后端、1 名前端、1 名集成/QA、产品负责人可及时审核需求。团队人数或并行度变化时重新估算。
- 人日为一名熟悉项目技术栈的开发者的粗略编码/评审工作量，不含等待真实 Provider、账号审批、产品决策和外部软件验证的时间。
- 当前没有具体人员名单，因此负责人栏标为角色/待分配；任务可以拆给其他人，但不能并发修改同一 ORM 模型或迁移头。
- 所有任务状态目前均为「待启动」。近期的模式门禁只属于临时防误用措施，不计作已完成生产能力。

## 并行与串行规则

### 必须串行

1. D-01 → D-02/D-03：先冻结模式与版本合同，再改数据库。
2. J-01 → J-02 → 依赖任务队列的 Provider/媒体作业：先有统一任务 ID 和 Attempt，再接各模型。
3. N-01 → S-01 → V-01/V-02/V-03：来源、映射和剧本版本必须先稳定。
4. TL-01 → TL-02/TL-03：前后端共用同一个时间线版本合同。
5. 三条产线具备真实候选与交付后再完成 QA-01。

### 可以并行

- I1 中 J-02、P-01、AS-01 在不同负责人下并行；数据库迁移由一位后端负责人合并，其他分支只提交模型/API 变更，不自行推进 migration head。
- I2 中前端 J-03/AS-02/N-03 在对应 API schema 冻结后并行。
- I4 的 AG-01 与 TL-01 可由不同后端负责人并行；二者共享任务/媒体引用合同但不共享写入模块。
- I5 的 AG-02、TL-02、TL-03、C-01 可按冻结接口并行；C-01 不得直接改时间线 schema。

## 单任务开工/收尾卡

每个任务正式分配时增加负责人、分支/工作树、目标版本、API/DB 合同链接和预估日历日期。完成时更新状态、实现提交、迁移号、验收操作/命令、未完成边界和下游任务。代码任务采用一个聚焦提交；未满足任务出口条件不得标为完成或开启依赖任务。
