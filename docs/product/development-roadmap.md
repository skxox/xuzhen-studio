# 叙帧产品开发路线图

本文件把 [生产平台功能规格](production-platform-spec.md) 转成可拆分、可并行和可验收的研发任务包。领取级的功能点见 [功能任务卡](feature-backlog.md)，相对迭代与工作量见 [执行计划](execution-plan.md)。完成定义以可运行的业务闭环为准，不以页面存在、路由返回 200 或模型任务提交成功为准。

## 当前基线

| 能力 | 当前状态 | 研发判断 |
|---|---|---|
| AI 原创小说 → 成片 | 有主要 API 与页面流程；依赖真实文本/图像/视频/TTS Provider 和本机 FFmpeg；未完成端到端产品验证 | 不把代码串联视为已验收闭环 |
| 已有小说 → 成片 | 可导入章节，但缺通用来源锁版与映射模型；视频/配音接口曾被 `original` 模式条件以 422 拒绝 | 需要统一来源与分集/剧本上下文，不能只删除模式判断 |
| 商品/广告 → 成片 | 有商品简报入口；没有完整事实证据、广告剧本和媒体候选路径；视频/配音也被模式条件拒绝 | 单独建立商品事实与广告规则，不复用小说门禁冒充支持 |
| 资产管理 | 有角色参考资料草稿和少量阶段内引用；没有完整的资产身份、版本、跨镜复用、影响分析与恢复 | 需先定义稳定 Asset/AssetVersion/Reference 合同 |
| 时间线剪辑与工程导出 | 有剪辑包、SRT 和 FFmpeg 母版首版；没有用户可编辑的多轨时间线及可继续编辑工程 | 独立时间线域和导出格式适配器 |
| AI 编排画布 | React Flow 展示阶段与任务状态；图是只读观察视图，不是持久化 Agent 执行图 | 先有 Run/NodeExecution 服务，再连接可观测与控制操作 |
| 后台任务 | 视频供应商异步任务由页面轮询；没有本地 worker、可靠队列、Attempt、重试/取消和进程重启恢复 | 媒体规模化前必须建立持久任务底座 |
| Provider / 成本 | 有 OpenAI-compatible 多模态首批 Adapter；任意兼容厂商能力未验证；缺统一估算/实际费用流水 | 建能力声明与用量追踪，避免“兼容协议即能力可用” |

近期阶段可用性保护只防止尚未支持的模式被空验收；它不等于功能已实现。后续完成对应的后端门禁、候选物化和前端路径后，才能将该模式标记为可用。

## 里程碑与顺序

```text
M0 产品/领域合同与数据库迁移
 ├── M1 持久任务与 Provider 能力/成本 ─┐
 ├── M2 资产库与版本/引用 ─────────────┼── M3 小说双入口 → 视频统一生产链
 └── M4 Agent 运行图与人工门禁 ────────┘                 │
                                                        ├── M5 多轨时间线/合成/工程导出
                                                        └── M6 商品/广告 → 成片
                                                                   │
                                                                   M7 端到端硬化与可部署
```

M1、M2 可在 M0 的实体和 API 合同冻结后并行；M4 可先做运行图服务和 UI 只读协议，但不能宣称具备 Agent 执行；M3 依赖 M0、M1，并通过 M2 的资产引用接口逐步接入；M5、M6 依赖媒体候选合同；M7 最后覆盖三类入口和恢复路径。

## 可委派任务包

### M0：数据基础与迁移

**CORE-01｜拆分内容来源、叙事形式和媒体路径**（后端/数据）

- **依赖**：无。
- **范围**：定义 `source_kind`、`content_mode`、`video_mode`；建立通用 `SourceRelease`/来源引用，支持已导入文本、AI 原创稿、成品剧本和商品素材的不可变版本快照；设计旧 `creation_mode` 到新字段的迁移与兼容读取。
- **交付**：领域模型、迁移脚本、应用服务、API schema、兼容矩阵和回滚方案。
- **验收**：旧项目可读取并按确定规则迁移；锁版后章节/文件修订会创建新来源版本；hash、权利状态和段落引用可查询；SQLite 与 PostgreSQL 迁移路径明确，不允许只靠 `create_all` 改现存表。
- **可并行**：完成字段/API 草案后，Provider 能力目录可独立设计；实现期间不并行改同一组 Project/Source ORM 模型。

**CORE-02｜阶段产物与依赖合同**（后端/产品）

- **依赖**：CORE-01 的项目模式矩阵草案。
- **范围**：统一每阶段的输入类型、候选类型、持久化产物、状态迁移、人工门禁、stale 传播、错误恢复和模式可用性；为“支持/计划中/不支持”提供服务端能力响应。
- **交付**：阶段合同表、转移规则、错误码目录、API schema 和示例数据。
- **验收**：任何阶段只有在必需候选和产物通过结构校验后才能接受；每个失败都有修复入口；三类来源和叙事/媒体组合都有显式策略，不再由零散 `creation_mode` 条件猜测。

### M1：持久任务、Provider 和成本

**JOB-01｜Run/Batch/Task/Attempt 与可靠派发**（后端/基础设施）

- **依赖**：CORE-02 的 task contract。
- **范围**：建立持久任务状态、幂等键、Attempt、outbox、队列、worker、并发限制、重试、取消、心跳、启动恢复和任务事件；API 返回持久任务 ID，不在 HTTP 请求中等待模型完成。
- **交付**：worker 入口、队列接口、任务查询/重试/取消 API、迁移、运维配置和故障恢复说明。
- **验收**：API/worker 进程在 queued、submitting、running、collecting 任一阶段重启后可恢复；重复请求不产生重复计费任务；取消后不再提交新的下游节点；远端 provider task ID 与最近心跳持久化。
- **可并行**：前端任务列表可基于冻结后的 Task API 合同单独开发；不得自行模拟任务成功态。

**PROV-01｜Provider 能力声明、参数校验与费用流水**（后端）

- **依赖**：CORE-02、JOB-01 的 Task/Attempt 合同。
- **范围**：文本、图像、视频、音频/TTS 和合成能力的 Adapter registry；能力探测、参数 JSON schema、同步/异步协议、轮询/取消、错误归一化；估算价、实际用量、币种、费率快照、失败费用。
- **交付**：Adapter 协议、首批 OpenAI-compatible adapters 的能力声明、Provider profile schema、usage ledger API。
- **验收**：不支持的参数/能力在提交前失败并说明原因；秘密不进入浏览器或日志；费用未知表示为 unknown；每个 Attempt 均可关联模型、实际用量和金额来源。

### M2：资产库

**ASSET-01｜资产身份、版本、参考图和来源关系**（后端/数据）

- **依赖**：CORE-01、CORE-02。
- **范围**：角色、场景、道具、商品统一身份模型；资产版本、图像/视频衍生、别名、视觉约束、来源证据、跨集引用、替换、合并、恢复和删除语义；媒体文件与元数据分开存储。
- **交付**：Asset/AssetVersion/AssetReference API、迁移、访问控制和变更影响服务。
- **验收**：分镜引用具体资产版本；替换资产不改写旧生成快照；用户可追踪资产出现在哪些剧本/镜头/任务；删除被引用资产时系统阻止或走明确归档流程。

**ASSET-02｜资产库工作台与生产阶段选择器**（前端）

- **依赖**：ASSET-01 的冻结 API schema。
- **范围**：资产分类/搜索/筛选、详情和版本历史、参考图预览、引用位置、批量审核、冲突/重复处理；剧本/分镜引用资产的选择和新增资产审核。
- **交付**：全局资产库页面和复用的资产选择/详情组件。
- **验收**：可从资产页查看来源和版本；资产修改展示下游影响；生成界面引用准确版本；所有按钮都有可用状态、确认行为和错误反馈。

### M3：小说双入口到成片

**NOVEL-01｜已有小说导入、来源锁版与分集映射**（后端）

- **依赖**：CORE-01、CORE-02。
- **范围**：章节/成品剧本导入拆分预览、SourceSpan、权利状态、版本哈希和不可变来源发布；AI 章节—分集映射候选及人工审核。
- **交付**：导入/预览/确认/锁版 API、source artifact、mapping candidate schema 和候选物化。
- **验收**：导入小说可创建有效 `SourceRelease`；映射输出需完整覆盖锁定范围且遵循用户目标时长；任何编辑产生新版本并让受影响下游过期；映射可审阅、修订、回滚。
- **可并行**：前端导入预览可在 API schema 冻结后委派；数据迁移与修改 `ManuscriptRelease` 的任务不得并行冲突。

**NOVEL-02｜AI 原创小说输出统一来源合同**（后端/前端）

- **依赖**：CORE-01、NOVEL-01。
- **范围**：简报、故事圣经、大纲、角色圣经、逐章生成、连续性 findings 和作者锁版均投影为通用 SourceRelease；保留逐章版本修订与风险审核。
- **验收**：AI 原创稿和导入稿从锁版后共用同一改编规划、资产、脚本、分镜、媒体任务与交付路径；两类入口的差异仅由来源策略决定。

**STORY-01｜统一故事规划、剧本结构和连续性**（后端/Agent 提示）

- **依赖**：NOVEL-01、ASSET-01、JOB-01、PROV-01。
- **范围**：章节证据映射、分集卡、场景、节拍、对白/旁白、时长预算、资产引用、连续性规则和结构化候选校验。
- **验收**：结构化数据能回跳原章节/段落；计划中的角色/场景/道具都能定位到资产 ID 或作为新增资产待审；错误 JSON 不进入 accepted 状态；单集可独立重新生成。

**MEDIA-01｜关键帧、视频、配音生成与审核**（后端/前端）

- **依赖**：STORY-01、ASSET-01、JOB-01、PROV-01。
- **范围**：分镜图和参考图两种视频路径；关键帧/视频/对白或旁白音频逐项任务；候选、审核、单项重做、历史版本、实际用量；按支持矩阵允许 `adaptation` 与 `commercial` 使用共享 Adapter。
- **验收**：不因 `creation_mode != original` 返回无业务依据的 422；每种视频路径有适配器输入校验；候选冻结资产、脚本和分镜版本；待审候选被人工处理前不得进入时间线；失败可重试且不重复计费。

### M4：AI 编排与人工控制

**AGENT-01｜可持久化工作流运行图**（后端/Agent）

- **依赖**：CORE-02、JOB-01、PROV-01。
- **范围**：Agent 生成计划、计划校验、NodeExecution、节点输入/输出、依赖、策略、运行上下文、暂停/恢复/取消和人工审核节点；AI 计划需满足固定领域合同。
- **交付**：Run/Node API、调度服务、人工节点事件和审计记录。
- **验收**：Agent 不能自行越过门禁或改变预算/权利策略；人工能改计划参数；节点失败只重跑受影响分支；输入变化使运行计划和产物明确标 stale；无 Agent 时仍可人工逐阶段完成。

**AGENT-02｜React Flow 可观测与控制台**（前端）

- **依赖**：AGENT-01 冻结 NodeExecution/Run API。
- **范围**：运行图状态、节点参数和 I/O 检视、待审高亮、运行/暂停/恢复/重试/取消、选中分支重跑和刷新恢复。
- **验收**：刷新或切页后恢复同一运行视图；节点状态来源于服务端；只允许执行后端开放的控制动作；人工审核有结构化确认与拒绝理由。

### M5：编辑时间线与交付

**EDIT-01｜多轨时间线领域模型和编辑 API**（后端/数据）

- **依赖**：MEDIA-01、JOB-01。
- **范围**：Timeline/Revision/Track/Clip/Transition/Caption/Mix 等版本化实体；视频、对白、旁白、音乐、字幕、片头片尾；裁切、分割、排序、替换、音量、淡变和撤销/恢复。
- **验收**：用户编辑不修改源媒体候选；保存版本可回退；轨道时间码无负值/越界/非法重叠；引用过期素材时提示并给出替换/确认入口。

**EDIT-02｜时间线工作台、预览、渲染和工程导出**（前端/后端媒体）

- **依赖**：EDIT-01、JOB-01、PROV-01。
- **范围**：可视化多轨剪辑、媒体预览、低清代理、版本历史、异步 FFmpeg 渲染、质量检查、MP4 输出和可继续编辑工程格式导出。
- **验收**：保存、预览、渲染和导出是不同明确动作；渲染输入快照可追溯；失败可从任务页恢复；导出内容与 timeline revision 一致；第一目标格式需在真实剪辑软件打开验证，兼容范围单独写明。

### M6：商品与广告短片

**COM-01｜商品事实、素材证据和广告创作链**（后端/前端/Agent）

- **依赖**：CORE-01、ASSET-01、STORY-01、MEDIA-01。
- **范围**：商品多图/视频、名称/规格/价格/卖点事实来源、受众、平台、禁用宣称、CTA、广告脚本、商品资产和镜头引用；无商品图时允许创意简报入口。
- **验收**：模型输出的功效/参数/认证/价格均有证据引用或待核实标记；事实变更使相关脚本/镜头过期；广告素材经过审核后进入共享时间线与导出链。

### M7：上线与整体验收

**SHIP-01｜端到端场景验证、安全和部署**（集成/QA/运维）

- **依赖**：NOVEL-02、MEDIA-01、EDIT-02、COM-01。
- **范围**：三类入口完整生产、Provider 配置/权限、任务恢复、备份/迁移、对象存储、 worker 部署、配额、恶意媒体扫描、可观测性和升级流程。
- **验收**：已有小说、AI 原创小说、商品/广告三条验收剧本均可由干净数据库跑通；关闭浏览器和重启 API/worker 后可恢复；至少一套真实文本、图像、视频、TTS Provider 完整验证；导出可以在目标软件打开；不存在仅页面显示“完成”的空产物状态。

## 可并行委派规则

一个任务包可交给独立开发者的条件：输入/输出 schema 已冻结、写入目录或模型边界明确、有独立验收条目、不会同时修改同一数据库迁移或核心类型。推荐拆分：

- **后端领域组**：CORE-01 / NOVEL-01 / ASSET-01 / EDIT-01；同一时间只允许一个任务修改迁移链和共享实体。
- **任务与 Provider 组**：JOB-01 / PROV-01；以 Task/Attempt 规范为共同契约。
- **前端工作台组**：ASSET-02 / AGENT-02 / EDIT-02 UI；先用明确 API schema，不内造假数据状态。
- **内容与 Agent 组**：STORY-01 / AGENT-01 / COM-01；仅负责输出合同、计划和领域校验，不能绕开普通服务直接写任意 JSON。
- **集成组**：MEDIA-01 / SHIP-01；负责供应商适配验证与端到端运行证据。

## 任务领取模板

后续每个委派任务从本文件选一个 ID，并补全：负责人、分支/工作树、涉及文件、输入合同版本、交付物、验收命令或操作、风险/阻塞项。一个提交只完成一个可审阅的任务包子项，使用中文 Angular 提交规范；未通过验收不能标记完成。开发者可并行，但核心 API/schema 冲突先通过短 ADR 解决。

## 下一项执行任务

当前应从 **CORE-01：来源、叙事和媒体模式解耦 + SourceRelease 迁移设计** 开始。它解除两条小说入口被绑在 `original` 模式上的根因，并为商品来源与后续 Provider 门禁提供稳定合同。在此合同定稿之前，不再实现孤立的时间线按钮、画布节点编辑或仅移除 422 判断的补丁。
