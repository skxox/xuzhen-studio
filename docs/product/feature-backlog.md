# 叙帧功能任务卡

这是按功能点拆分、可独立领取并通过 PR 验收的清单，便于更多参与者按边界协作。整体目标与验收场景见 [生产平台功能规格](production-platform-spec.md)；功能依赖顺序见 [执行计划](execution-plan.md)。

## 功能卡片使用规则

- 每张卡描述一个可实现、可审阅的功能边界；API 与前端需要独立交付时，可继续拆成关联子卡。
- 任务卡未满足依赖时不得提前实现会造成返工的 schema 或页面状态。
- 共享数据库迁移和核心 schema 必须遵循明确依赖顺序，避免并行变更造成冲突。
- 每张卡完成后记录分支/PR、实现提交、迁移号、验收证据、遗留项和后继卡；通过验收后才改状态为完成。
- 每张卡使用一个聚焦 Angular 中文提交；不要把多个无依赖功能点打包成大 PR。

## 可并行功能边界

- Provider 能力目录与资产身份/版本可在领域合同冻结后分别推进。
- 前端任务列表、资产库、Agent 画布和时间线界面可在各自 API 合同冻结后独立实现。
- Agent 运行图与时间线编辑可并行演进，但分别依赖持久任务/媒体产物合同。
- 小说和广告路径复用媒体、任务与交付能力；商品事实账本及广告规则保持独立领域边界。
- 修改共享 ORM、迁移或 API 类型前，先确认对应前置卡的合同已冻结；避免多人同时改同一边界。
